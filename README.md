# 大明 · 御览

> 工作文档已于 2026-09-10 分类整理：[工作文件总入口](docs/README.md) · [系统索引与实现状态](docs/00_项目总览/系统索引与实现状态.md) · [系统设计模板](docs/99_模板/系统设计模板.md)。

Python + PySide6 的皇帝角色模拟游戏框架。现阶段可以按整旬 30 AP 规划工作与私生活，依次执行活动，处理场景选择、朝政、急报和未来预约；支持三旬日程、皇帝档案、明代史料浏览，以及独立的一县经济试玩。

**M03 三阶段行动与一县经济已实现。** 县经济仅在明确开启的演示局运行，实际计算生产投入与产出、三池余额、居民消费、短缺死亡及财富降层，随同一旬末保存。普通局与无经济数据的旧档保持原规则。全国财政、税制、运输、官员 AI、忠心与政府声誉仍未模拟；改税、任命与修渠尚不产生实际经济效果。皇帝健康仍可手动调整，县民健康另行计算。

史料暂以约 1500 年、弘治十三年正月为工作基准，尚未锁定正式开局。地图采用两京十三布政使司的治所参考点，明代行政边界尚未复原。

## 启动

Windows 源码版在项目目录中运行：

```powershell
uv sync --locked --all-groups
uv run dynasty
```

也可双击根目录的 `启动游戏.cmd`。脚本使用 `uv run --locked dynasty`，需要本机可用的 uv。Python 版本范围为 3.12–3.13，本次开发使用 3.12.13；依赖由 `uv.lock` 锁定。uv 安装方法见 [官方安装文档](https://docs.astral.sh/uv/getting-started/installation/)。首次同步需要下载解释器或依赖；已有完整环境及数据后，游戏可以离线运行。

县经济打包版入口为 `dist/MingImperialDesk-CountyV2/MingImperialDesk-CountyV2.exe`，已验证独立程序启动与演示存档读取。已有三阶段打包版 `dist/MingImperialDesk-M03Stages/` 及前版 `dist/MingImperialDesk/` 保留。目录式程序须保留整个对应文件夹及 `_internal` 内容，不要只复制 EXE。

从源码重新打包：

```powershell
uv run python tools/build_windows.py --name MingImperialDesk-CountyV2
```

该命令需要开发依赖并在 Windows 执行，生成目录式程序；当前没有安装器或签名安装包。

## 体验一县经济

主菜单选择 **“县级经济试玩”**，选择正常供给、持续缺粮或生产投入不足，建立虚构的清河县；也可双击 **`体验县经济.cmd`** 直接打开正常情境。脚本优先使用县经济打包版，不存在时从源码启动。命令行入口为：

```powershell
uv run dynasty --county-demo normal
uv run dynasty --county-demo shortage
uv run dynasty --county-demo input_shortage
```

县内初始人口为 1,000 人，按农民、劳工、手工业者、商人、地主、贵族、官员七类职业统计；财富另由人均收入评为贫困、普通、富裕。默认劳动力比例 50%，年出生率 3%、年自然死亡率 2%，取消年龄组。详见[人口职业与收入](docs/01_系统设计/M05_M06_财政与地方经济/M06_人口职业与收入.md)。全部初值、土地面积与资源单位均为演示配置，不是清河县的历史复原。

1. 左栏 **“07 县档案”** 提供人口、土地、当地特产、当地修正、钱粮与物资、基础设施、生产经营、民情与秩序八个栏目。
2. 点击 **“休息并推进一旬”**，明确把皇帝本旬安排为完整休息，通过同一旬末结算一次经济，并打开旬报。已有具体活动、当旬急报、预约、三旬计划或未提交活动草稿时会提示先处理；也可继续通过起居与朝政正常行动。
3. 在 **“钱粮与物资”** 中，旬初可试调所选民间、官府或皇家池的资源余额。缺粮影响各财富层的健康、满意、劳力、死亡和降层；缺少生产原料会限制产业进度。各池不会自动混用，查看与刷新不会结算。

县情、生产阶段、三池余额、人口后果和历史旬报可随当前局保存、读取。正式税收、跨县运输、市场交易、建设升级及官员 AI 尚未接入。完整操作与演示规则见[县级经济试玩说明](docs/03_试玩与验收/M06_县级经济_试玩说明.md)。

## 体验 M03 三阶段

双击根目录的 **`体验M03.cmd`**，打开三阶段示范。也可运行 `uv run dynasty --m03-demo`。示范局预先登记一份按阶段送达的急报，方便试玩；不会读取或覆盖玩家存档。

1. 旬初默认勾选早朝，固定 5 AP、置顶且每旬最多一次，可取消。正常健康默认为“早朝 5＋其他工作 15＋私生活 10”。
2. 其余任务按工作、私生活分组，只能在同阶段内调整顺序。**可以预排，也可以留空到执行阶段临时选择，不再要求旬初排满。**
3. 进入“日程 · 执行”，按早朝、工作、私生活依次推进。临选区只提供本阶段任务，办公任务可设置本段投入 AP。
4. 工作阶段可提前结束，将真正未使用的时间转入私生活。实际工作进度保留；尚未开始的工作撤下，未完成活动不计完整完成。私生活不能反向转回工作。
5. 有非早朝工作预算时急报在工作中点触发；没有其他工作时，在非最后一项私生活行动中触发。送达位置及内部进度随存档保存。
6. “未来预约…”与“安排连续三旬…”继续可用；三旬各自支持部分预排。全部时间实际使用完后才提交旬末结算。

新局健康档位暂为 10／20／30 AP，只按整旬安排。新局存档版本为 3；v1／v2旧档保留原规则与执行位置。完整说明见 [M03 三阶段行动](docs/01_系统设计/M03_回合行动/M03_三阶段行动_试玩说明.md)。

主菜单提供开始、县级经济试玩、读取、设置、退出；自定义剧本可填写皇帝、年号、年月旬及健康，保存于 `%LOCALAPPDATA%/MingDynastySimulator/scenarios/`。普通自定义开局不会自动启用县经济。自动保存尚未启用。

## 皇帝属性与技能

游戏内左栏点击“06 皇帝档案”。“基础属性”页签按智力、身体、意志三类展示全部 13 项；“技能”页签展示政务处理、军事策略、识人能力、话术、书法、学识，点击卡片查看说明；“性格与追求”页签展示九组稳定性格、近期欲望与长期野心。姓名、年号和健康读取当前游戏。

点击“手动调整…”可修改全部属性与技能，应用前统一校验，取消不改变数值。允许超过 100 的非负整数，技能不被基础属性封顶；修改不消耗行动力、诏书，也不推进时间。修改后使用右上角“保存”保留到存档。编辑不会清空朝政页尚未提交的活动安排。

基础属性页右侧的**健康栏**显示整体健康度与压力（0–100）。只有患病、受伤或残疾的身体部位才显示明细；健康时整段明细隐藏。“调整…”可录入异常部位、状态和压力，也可修改整体健康。健康导致 AP 变化时会校验当前活动、三旬计划和未提交草稿，存在冲突则拒绝修改。

**当前修正**栏用“管理…”增加、删除长期或短期效果。属性修正按点数相加，显示底值和当前值；技能效果按百分比点相加，技能页显示效果比例，熟练度不变。长期保留至移除；短期暂按剩余旬数，每成功完成一旬扣 1，归零后移除。暂停、刷新与读档不扣时长。健康记录不会自行生成疾病惩罚，具体疾病与修正来源后续设计。

压力默认 0、异常与修正默认空，旧存档自动补充。健康、压力、异常部位、修正和剩余时长全部随当前局保存。

**性格与追求**保留仁厚—严酷、宽信—多疑、守成—求变、质朴—奢华、放权—掌控，增加谦逊—自负、重情—秉公、守信—权宜、合群—独处。九组暂用 0–100 量表，50 居中，均为可调整的演示值；不另列心理状态，心理影响归入健康页已有压力、身体和修正。

近期欲望与长期野心可自设名称、说明、对应活动和目标次数。点击“安排…”将相应活动加入尚有预算的本旬日程；本旬已排满时保留原安排。必须实际完成对应活动才增加进度，被替代活动和暂停不计。达标自动留下满足／达成记录，未完成目标可撤下；完成记录与进度可保存，不会因读档重复增加。当前目标完成不自动发放压力减免、属性或金钱奖励；性格学习公式、自动欲望产生与具体满足效果仍待设计。

**基础属性 50、技能 0 只是演示初值，不代表历史人物评价，也不是正式量表。** 尚未启用学习成长、技能等级或事件判定；页面说明保留“同技能常规表现相同，事件结合相关属性与技能”的已确认原则。

年度宫廷供给已记为定额、每年朝议，暂定一年一拨。县演示的皇家池记录当地皇家产业产出；国库、内帑完整收支和年度拨款流程仍待实现。

健康与修正的页面样例可运行 `uv run python tools/capture_emperor_status.py` 生成，七幅截图和标注为演示的存档位于 `artifacts/`；样例不写入玩家存档。

性格与追求的七幅预览、编辑器和独立演示存档可用 `uv run python tools/capture_emperor_motives.py` 生成。直接截图第三页签可用 `uv run dynasty --page 5 --emperor-tab 2 --screenshot artifacts/emperor-motives-preview.png`。

## 急报与三旬计划

新规则下，仅早朝提供急报朝政覆盖；普通诏令只有当前正在早朝时开放。急报可在活动或场景阶段之间暂停，保留读书主题、习武轮次、宫苑去处及办公进度。有早朝安排不额外占 AP；无早朝须中止一项未完成活动，不返还已用时间，该项剩余预算由急报占用。没有未完成卡片时，可明确使用本阶段尚未安排的 1 AP 处理急报；没有有效送达位置则留待下一旬，不追溯取消已完成活动。

应急命令可以透支诏书，普通朝政不可以。欠额从下一旬额度扣还；超过单旬额度的部分继续跨旬扣还。“阅报并交地方续处”只登记交办意图，不触发地方 AI。

三旬计划从当前旬开始，分别保存已预排的顺序和阶段预算，允许留空到阶段中临选。预拟政令到早朝才执行并检查额度与 CD，遇到劝谏或额度不足保留未执行命令，必要时可明确取消。“继续三旬计划”进入当前未完成阶段，活动选择仍由玩家处理。新旬会载入对应计划，不无声清空。

预约独立于三旬计划，可以更远。改期与缺席分来源保存后果，国家关系和资源数值暂不扣减；重复打开或读档不重复处罚。

## 存档与记录

右上角“保存”“读取”使用 JSON 文件。默认保存位置为 `%LOCALAPPDATA%/MingDynastySimulator/弘治_存档.json`，也可自行选择路径。日期、活动、诏书欠额、CD、计划、待回应急报与劝谏一起保存；读取不会重新生成事件。新局不会自动保存上一局。

“诏令与起居簿”记录下令、透支、暂停和推进。剧本名称、皇帝姓名、年号及皇帝属性与技能随存档保存，游戏中的年号年份会随时间推进。三阶段新局存档版本为 3，保存回合阶段、活动游标、场景阶段、剩余预算、单向转时、急报位置、待办与预约；v2完整预排局继续按v2运行。v1 旧档继续按旧规则读取和保存；缺失的早期皇帝档案补充演示初值，存在但损坏的数据拒绝读取，不擅自换算旧局。

县经济使用可选的 `economy` 数据，结构与规则版本各为 1，仅在 v3 县演示局启用。旧档缺少该字段时继续关闭经济；存在但损坏的数据拒绝读取。县经济新档不保证能由旧版 EXE 打开。

## 地图与史料

“天下舆图”支持缩放、拖动、选择治所点、查看府州卫司和县名，并把所选大区带入拟旨界面。底图是 Natural Earth 陆地轮廓；点位采用现代城市参考坐标，不等于精确明代城址。

“史料书库”支持检索、查看来源、原文证据和年代说明。当前收录 13 名人物、54 条官职、13 条法令与法律主题、15 个大区、654 条府州卫司等行政索引，以及 1,173 个县名。**下级行政索引包含不同时期沿革，未认定全部在 1500 年同时存在。** 法令中也有晚出或晚于正月的资料，适用性逐条标注。史料书库是研究工具，不代表皇帝在游戏世界中已知这些信息。

1580 年参考图单独展示，不能用作 1500 年版图。书目、下载时间、SHA-256、许可与待核问题见：

## 项目结构

| 路径 | 用途 |
| --- | --- |
| `src/dynasty/core/` | 不依赖 Qt 的状态、逐旬流程、命令检查和存档 |
| `src/dynasty/core/regions/` | 一县模型校验、生产、消费、人口后果与统一经济结算 |
| `src/dynasty/ui/` | 桌面页面、地图、计划和诏令编辑器 |
| `src/dynasty/content.py` | 历史数据、演示配置与资源路径读取 |
| `data/config/framework.json` | 新局演示额度、健康档位和起始时间 |
| `data/config/county_demo.json` | 虚构清河县、三种情境与可替换的经济演示参数 |
| `data/history/` | 结构化史料、来源清单与原始下载 |
| `assets/` | 字体及来源与许可 |
| `tools/` | 下载、整理、校验和打包脚本 |
| `tests/` | 核心流程与界面测试 |
