## 当前实现状态（2026-09-07）

内帑收入结算、年度供给拨付、财政划拨及官员阻止机制尚未实现；下文“一年一拨”属于用户指定的暂定设计。

当前可运行工程已采用 **Python + PySide6 + uv**。已经接入行动分配、朝政多令、诏书额度、改税劝谏、应急透支、连续三旬计划、存读档、治所参考点地图与史料浏览。国家数值模拟尚未启用：推进改变时间、流程状态和行动／诏书账目；人口、钱粮、健康、民心、忠心等保持不变或尚未赋值。政令的世界后果只登记为意图及待处理效果。

皇帝档案页面已接入 13 项基础属性、六项技能、手动调整与存读档；当前有基础属性、技能及性格与追求三个页签。基础属性 50、技能 0 是演示初值；支持超过 100 的非负整数，不以基础属性封顶技能。正式量表、学习成长与事件判定尚未启用。

基础属性页已加入健康栏与修正栏：整体健康度／压力 0–100、异常身体部位、长短期属性及技能效果修正。状态可手动管理并保存，修正当前按属性点数／技能百分比点叠加，短期按完成旬递减。具体疾病、压力自动变化与正式效果规则仍待设计。

新增“性格与追求”页，显示九组性格及近期欲望／长期野心。当前使用居中性格演示值和玩家自设的活动完成目标，成功旬结算推进目标并记录满足；自动欲望产生、人格影响与具体满足奖励尚未启用。不新增心理状态栏。

第 1 节继续保留用户已确认原则；后续架构和系统说明是完整游戏的目标或建议，不能据此认为官员 AI、情报模糊、国家经济、长期工程与私生活效果已经实现。健康档位、每旬 3 份诏书、改税 CD 3 旬等演示参数不构成新的设计确认。

| 历史关系 | 使用真实朝代作为开局，之后由玩家与世界模拟产生可能偏离史实的发展。 |

| 内帑收入 | 由年度宫廷供给定额、皇家产业收益和临时进项构成。常规国库供给已由比例改为定额，每年在朝堂商议对应年度的额度，拨付节奏暂定一年一拨。具体金额、议定流程、年内具体拨付时点、未议定或国库不足时的处理，以及皇家产业与临时来源的具体规则待定；尚未实现。 |
| 国库用于宫廷享乐的划拨 | 皇帝须在朝堂提出划拨方案。大臣是否劝谏及反对程度取决于当前国家财政与大臣性格；财政糟糕且大臣清廉、坚持道德原则时，会强烈反对。若该反对者是户部尚书或相应财政主官，在罢免他之前不能进行这笔划拨；之后由新任财政主官重新处理原方案，其性格仍影响态度。任命程序、职位空缺、办理成本与罢免后果待定，尚未实现。 |

| 政务频率限制 | 不同政务操作有各自的 CD。税率在 CD 内再次修改会触发大臣劝谏；听取则不修改，坚持则执行并承担惩罚。其他政务的具体 CD 响应尚未逐项确定。 |
| 频繁改税后果 | 一意孤行会降低大臣忠心与政府声誉，降低其他政令效果。若本次是降税，仍有民心上涨收益，但被惩罚抵消大量。具体数值、作用范围和持续时间待定。 |
| 官员执行 | 属性、人格特质和少量随机性影响执行数值。具体公式与细节以后确定。 |
| 地方自主治理 | 官员自行决定地方事务，皇帝没有特定指派时地方仍持续运转。官员主要依据性格、能力，以及国家制定的大方向政策和法律决定处理方式。 |
| 地方事务可见性 | 皇帝没有特定指派任务时，可以看到并介入哪些地方事务，受情报机构强度和皇权强度影响。已知事务的干预权限与服从程度尚未单独确定，不能将可见性等同于执行权。 |
| 信息模糊 | 皇帝掌握的信息可以模糊、不完全，模糊程度与政府腐败度相关。 |

## 2. 建议的最小架构

围绕“世界实际状态—皇帝活动与官员自主决策—行动执行—逐旬结算—信息反馈”建立核心；月度规划作为同一核心的批量操作入口。皇帝没有发令时，官员和地方模拟仍然推进。

### 2.1 世界状态与玩家信息分离

- **真实世界状态**：国家与地方的实际情况，以及人物、政策、事务的运行状态。模拟规则读取这些数据。
- **官员掌握的信息**：建议单独保存其职责范围内的观察、报表及已收到的政策和命令；自主决策不默认读取所有地区真值。
- **皇帝掌握的信息**：奏报、调查结果、估计范围、来源和更新时间。界面与月度计划预估使用这层信息。
- **皇帝可见的地方事务**：没有特定指派时，根据情报机构与皇权强度决定事务的暴露范围及程度；腐败影响获得的信息质量。具体合成规则后续确定。
- 世界已经发生一件事，不等于皇帝已经获知。紧急奏报的送达与世界事件的发生需要可以区分。
- 调查首先改变信息掌握程度；调查引发的后续处置再通过独立行动改变世界。
- 每份奏报保存自己的结果，重复打开同一份奏报不重新随机生成数字。
- 信息覆盖、信息准确度和命令执行效果分开记录。提高情报机构强度不会直接改变地方的真实粮食或自动令官员服从。
- 特定指派建议建立专门的任务与汇报渠道，但是否带来额外可见性、可见到何种程度仍待定，不默认使相关地区完全透明。

信息模糊的具体形式、腐败度的范围与计算方式仍待定。可以先采用全国政府腐败度，数据结构为地方或部门差异预留位置。

### 2.2 统一人物与行动模型

皇帝、官员及未来的宫廷人物共享基础人物身份、健康、属性、特质和关系数据。不同角色仅启用适用的能力与规则。

皇帝能力已确认采用“基础属性＋技能”两部分。基础属性为第 1 节列出的三类 13 项，变化相对缓慢和固定；政务处理、军事策略、识人能力、话术、书法、学识等属于可学习的技能，学习增长速度受基础属性和性格影响。不能继续把政务、识人等技能当作皇帝的基础属性。具体定义、学习关联建议与未决问题见[皇帝属性与技能设计](../01_系统设计/M01_人物能力与健康/皇帝属性与技能.md)。当前皇帝页面使用明确标注的演示数值，未将史料人物自动评分，也未启用成长结算；健康影响行动力的既有规则继续保留。

技能相同时，正常表现相同，基础属性不提供额外的常规技能表现加成。事件判定由相关基础属性与技能共同参与；相同技能与其他条件下，较高的相关基础属性提高成功可能性。学习、常规表现与事件判定分别定义，具体事件触发、难度与概率公式后续确定。

基础属性不限制技能成长上限，低基础属性人物可以通过足够学习达到同等技能水平。保留玩家作弊修改与超出常规数值的空间；常规等级标签不应成为技能的硬性上限。当前入口为“皇帝档案 → 手动调整”，采用非负整数，正式量表后续设计。

新增健康栏与修正栏的当前实现约定：整体健康沿用唯一健康值，压力默认 0；身体仅记录异常，疾病名称不自动生成惩罚。属性按有符号点数叠加，当前值最低 0，无固定上限；技能效果从 100% 起叠加百分比点，最低 0%，不改熟练度。长期至移除，短期按旬计，成功完成一旬扣 1，到 0 移除；暂停与读档不扣。手动健康修改如造成 AP 与活动或计划冲突，则原子拒绝。以上为页面实现约定，正式叠加、疾病、压力与期限机制继续讨论，详见[皇帝属性与技能](../01_系统设计/M01_人物能力与健康/皇帝属性与技能.md)。原有“同技能常规表现相同”原则比较相同修正条件，基础属性仍不直接加成所有日常技能表现。

政务与私生活共享活动安排入口和皇帝行动力核算。区分“皇帝的活动安排”和“活动中作出的具体决定”：处理朝政、读书、休息属于活动安排，拨款、任命等属于具体决定。

已确认：一次处理朝政可以执行多项普通政务，这些政务使用诏书资源限制数量，不逐项重复消耗安排朝政所需的行动力。当旬已有朝政安排时，处理急报不额外消耗行动力；急报所需诏书可以透支，透支量扣减下一旬额度。普通政令没有透支资格。

具体决定或活动可以使用各自的执行逻辑，例如调粮改变资源流向，读书改变个人成长进度。

建议把行动分为三类：

| 类型 | 例子 | 生命周期 |
| --- | --- | --- |
| 长期政策 | 税率调整、休养生息 | 颁布后持续生效，直到修改、到期或废止。 |
| 人事与委派 | 任命地方官、指定事务负责人 | 建立或改变持续的职责关系。 |
| 专项与个人行动 | 赈灾、修渠、读书、休息 | 可以立即完成，也可以创建跨旬持续的任务。 |

建议分别记录“活动所需行动力”“命令所需诏书”和“事务所需钱粮、时间”。一次朝政内的普通政令逐项检查诏书额度与各自限制，避免重复扣除皇帝行动力。急报的行动力豁免与诏书透支分别核算，不免除事务的钱粮或执行时间。维持已生效政策不重复视为皇帝再次下令；需要持续亲自投入的活动则单独声明行动力成本。

### 2.3 命令允许部分委托

一条命令同时记录：皇帝明确指定的参数、留给执行者决定的参数，以及适用的限制条件。

例如赈灾指令可以指定目标地区和负责人，调粮数量留空。官员在真正执行指令时，根据当时自己掌握的信息、属性与人格，补全数量。

建议执行步骤：

1. 检查所属朝政安排或应急处理资格、执行者身份、目标、诏书额度、CD 及资源等条件。只有紧急事件中的适用回应可以在诏书不足时透支，不能把该权限用于普通命令。
2. 由执行者补全允许委托的参数；只使用执行者能够获得的信息。
3. 检查补全后的方案是否满足指令限制及实际可用资源。
4. 对需要劝谏的命令，在提交前暂停并展示劝谏。税率 CD 内重改时，听取则取消本次修改，坚持才进入正式提交。国库用于宫廷享乐的划拨若遭财政主官强烈反对，则按已确认规则阻止执行，在罢免该主官之前不能划拨；不能套用改税的“坚持后执行”路径。
5. 成功下达命令时统一提交本次应付成本、诏书使用或透支记录、频率记录及适用的坚持惩罚，执行命令或创建持续任务。建议未成功下达的指令不消耗诏书、不启动 CD；下达后的执行失败或取消不等同于未下达，后续补偿规则单独确定。
6. 后续结算依据官员属性、人格特质、政府声誉等适用因素与有界随机因素计算效果，并记录原因。

“明确下令十万两”与“实际有效用于赈灾的金额”可以不同。差异应由能力、执行损耗或不当行为等规则产生并留有内部记录。对玩家展示多少原因，仍受信息规则约束。

### 2.4 诏书与政务频率规则

**已确认的三层限制：**行动力限制活动安排，诏书上限限制当旬政务下令量，政务 CD 与频繁操作惩罚约束政策反复变更。

**建议的可配置规则：**

| 配置 | 用途 |
| --- | --- |
| 诏书成本 | 每种命令可以配置不同成本；尚未规定一项政务固定消耗一份诏书。 |
| 本旬额度 | 记录本旬上限、已用量和剩余可用量。上限来源与补充方式尚未确定。 |
| 紧急透支记录 | 记录触发事件、回应、实际超额量与下一旬应扣额；透支资格来自紧急事件的适用回应。 |
| 限制作用对象 | 指定按全国、地区、职位或其他目标跟踪限制；避免一个省的操作意外锁住所有地区。 |
| CD 响应 | 可以表达劝谏、坚持惩罚或禁止执行等响应。已确认税率采用劝谏与坚持惩罚，不能将其写成绝对禁止修改。其他类型留待各政务定义。 |
| 频繁变更惩罚 | 表达允许再次执行但附加损失的规则；与禁止执行的期限分开，不能把两者混为一谈。 |
| 操作历史 | 保存操作类型、目标、颁布时间和政策变化等，以支持频次、幅度及反复撤销的判定。 |

税率变化流程：修改命令成功下达后记录时间与变化；之后在 CD 内再修改时，大臣劝谏。听取则保持原税率，坚持则执行修改并降低忠心与政府声誉，影响其他政令效果。“上次执行时间”足以支持简单 CD，更复杂的频繁调整规则还可读取一段时间内的变更历史。

以下为首版实现建议：

- 本旬的诏书使用记录由所有朝政活动和适用的应急命令共享；重新打开朝政界面或再安排一次朝政不自动重置额度。
- 维持已有税率和推进已开工工程，不等于再次颁布命令，不每旬重复扣除诏书或刷新操作时间。
- 玩家确认普通命令前，可以查看适用的诏书成本、冷却限制和可知的惩罚。月度计划只预估，真正下达时重新检查。
- 一项指令未通过检查时，保留其他尚未执行的指令，并暂停请玩家调整；不悄悄替换命令或造成重复扣除。
- 普通命令额度不足时不能透支；紧急事件的适用回应可以透支，并在下一旬更新额度时扣除应还量。未来计划根据扣减后的额度重新检查。
- 诏书是否允许剩余额度结转、透支上限、下一旬额度不足以清偿时的处理，以及其他政务的 CD 响应仍待细化；不得把行动力不结转规则擅自套用于诏书。

### 2.5 劝谏、声誉与政策效果

**已确认的行为：**

- CD 内再次修改税率时，大臣会劝谏。
- 听取劝谏，则本次修改不发生。
- 坚持修改，则降低大臣忠心、政府声誉和其他政令效果。
- 降税本身仍带来民心上涨，但频繁变更的惩罚抵消大量收益。

**建议的实现边界：**

- 劝谏属于命令提交前的决策节点。接受劝谏不扣本次诏书、不刷新上次改税时间、不触发坚持惩罚；已经安排的朝政活动不因此自动退还行动力。
- 坚持后，命令成本与惩罚只提交一次。反复查看劝谏、关闭界面或恢复存档不能再次扣除忠心和声誉。
- 忠心记录在适用的大臣身上；影响劝谏者、相关大臣还是更广范围，后续确定。
- 政府声誉、政府腐败度和民心分别保存：声誉参与政策效果，腐败参与执行与信息机制，民心描述民众反应。彼此可以关联，但不能合并为一个数值。腐败对执行的具体影响尚待定义。
- 降税对民心的贡献与频繁变更的惩罚分项记录；两项合成后保留被削弱的正向贡献，不能把“降税收益被大量抵消”直接写成“降税必然降低民心”。其他同期因素仍可能影响最终民心总变化。
- 对其他政令效果的削弱按效果含义处理，不机械缩放所有正负数值，以免出现声誉下降反而减少成本、降低灾害损失等反向结果。具体系数与适用范围后续确定。
- 暂不把同一声誉损失自动转化成反复、无限期扣除忠心。惩罚持续时间、恢复方式与是否叠加需要独立定义。

诏书透支采用独立账目记录。示例仅用于解释：若下一旬原有 5 份额度，本旬应急透支 2 份，则下一旬先扣减为 3 份。应急透支不因为新开朝政界面而清除，也不允许挪给同旬无关的普通政令。超出下一旬可偿还额度的情形留待后续规则确定。

### 2.6 地方自主治理、政策与法律

**已确认的行为：**

- 地方官会自行决定地方事务，不需要皇帝为每项事务发出命令。
- 官员的性格、能力、国家大方向政策和法律共同影响处理方式。
- 没有特定指派时，皇帝可见的地方事务受情报机构强度和皇权强度影响；奏报模糊仍与政府腐败度相关。

**建议的官员决策流程：**

1. 读取任职地区的已知情况、当前职责、已收到的具体指派，以及适用的政策和法律。
2. 识别待处理事务，查看自己已经推进的任务，避免每旬重新开始同一事项。
3. 从当前适用的地方措施中形成候选方案，例如处理灾情、安排地方支出、维护设施或上报求援。具体措施清单与自主权限尚待确定。
4. 依据性格形成偏好，依据能力估计成效与代价，结合国家政策、法律和少量随机因素选择方案。法律对候选方案是绝对限制还是允许违法但承担后果，尚待讨论。
5. 检查实际钱粮、人手及既有承诺，提交地方行动或推进任务。地方行动也使用统一的资源和效果结算入口。
6. 分别保存实际处置、内部决策依据和上报内容，再经情报、皇权与腐败相关规则形成皇帝能够获得的信息。

**政策、法律与指派的职责建议：**

| 内容 | 主要表达 | 可扩展的数据 |
| --- | --- | --- |
| 国家大方向政策 | 朝廷鼓励与优先追求什么，影响地方官对方案的取舍。 | 目标、优先级、适用地区、开始与结束时间。 |
| 法律与制度 | 哪些行为合规，官职通常具有什么职责与权限，以及违规后适用什么规则。 | 行为条件、适用对象、授权范围、法律后果；是否可能违背尚待确认。 |
| 皇帝具体指派 | 对某件事务的明确要求与委托空间。 | 目标、负责人、指定参数、留空参数、期限与汇报要求。 |

三者发生冲突时的优先级、官员是否可以抗命或违法及其后果，尚未确定。框架将它们分别保存，便于以后表达不同朝代制度。

**与现有系统的衔接建议：**

- 地方官自主处理通常由地方资源和职责权限约束，不逐项消耗皇帝行动力与诏书；需要皇帝批准的事项先形成请示，批准后的皇帝命令才进入对应额度核算。
- 皇帝具体指派与地方自主行动关联到同一个事务。明确参数保留为皇帝的原始要求，官员只补全委托参数；实际偏差单独记录，不能默默改写原始命令。
- 已有自主处置与新指派重合时，更新、协调或中止相关任务，不重复调粮、重复开工或重复扣费；具体冲突策略后续确定。
- 将“发现事务”“形成估计”“具备干预途径”“命令实际被执行”保留为不同判断。当前只确认情报机构和皇权影响无特定指派时的可见性，不能擅自推出皇权高就掌握全部真值或皇权低就完全不能下令。
- 地方决策及结果即使没有显示给皇帝，也会写入世界状态和存档；界面显示与否不能决定地方是否继续模拟。
- 地方官观察和制定方案与最终结算分开。跨地区的共享资源、调运请求先汇总与检查，再提交，避免一个地区的循环顺序无意改变另一个地区的决策条件。

缺粮场景的可讨论示例：地方官先根据当地已知缺口、性格能力和朝廷方针决定处置；皇帝可能只收到滞后的概况，也可能通过较强的情报渠道发现更具体的事务。此例只说明架构，不先确定粮价、迁徙、叛乱等后续机制。

### 2.7 国库划拨、劝谏与财政主官

内帑收入已确认由年度宫廷供给定额、皇家产业收益和临时进项构成。经历史核查后，用户确认将常规国库供给由比例改为定额，每年在朝堂商议对应年度的额度；拨付节奏按用户要求暂定一年一拨。具体金额、议定流程、年内具体拨付时点（年初、年末等）、未议定或国库不足时的处理与年度议定中财政主官的权限仍待确定；皇家产业和临时进项的具体来源及结算方式亦待细化。年度定额与年度朝议均为已确认游戏规则，一年一拨保留为暂定方案。

以下记录“内帑不足，皇帝希望动用国库修建供自己享乐的宫殿”这一场景的已确认规则，不自动扩展为所有财政支出均由财政主官否决。年度供给须朝议已确认，但该年度议定中的具体权限与僵持处理仍待讨论。

- 皇帝须在朝堂提出划拨方案。
- 大臣可能劝谏，也可能不劝谏，取决于当前国家财政状况与大臣性格。
- 财政糟糕，且大臣属于清廉、坚持道德原则的“道德卫士”时，会强烈反对。
- 若该强烈反对者是户部尚书或相应的财政主官，则在罢免他之前不能进行此项划拨。职位在本场景中提供实际阻止作用，不能用额外诏书、皇帝坚持或未经确认的技能判定直接绕过。
- 罢免后，由新任财政主官重新处理原划拨方案，其性格仍会影响态度；适用的财政状况与职权规则继续参与处理，换人不自动意味着通过或放款。
- 任命程序、职位空缺期间的具体处理、重新办理成本和罢免后果仍待讨论。

建议分别保存官员对方案的态度和官职对该事项的办理权限，记录被阻止的具体方案及主官；只提出或被阻止时不先移动钱款，实际调拨条件满足后再结算。提出方案、失败、重新提交各自是否消耗诏书尚未确定。财政评估指标、性格表达和具体流程见[皇帝资源与财政权力](../01_系统设计/M05_M06_财政与地方经济/皇帝资源与财政权力.md)。本次只更新设计，未启用财政模拟或官员否决机制。

## 3. 月度规划与逐旬执行

### 3.1 月度计划只安排未来行动

建议月度计划保存三个有序活动安排列表，分别对应上旬、中旬、下旬；朝政活动可以关联预先拟定的具体指令。规划时分别展示行动力预算、诏书使用量、CD 和成本的估计值，不立即执行行动、补全官员选择、扣除资源或启动 CD。

三旬分别记录行动力预算，不能把上旬剩余行动力留到中旬。进入实际执行旬时，按当旬健康校验预算，并要求当旬行动力全部分配到有效安排后推进。是否为未分配部分提供一键安排休息等便利功能，属于后续界面设计，暂不默认替玩家安排。

这样，月度规划与逐旬操作调用同一套规则。中旬执行时会使用中旬的实际状态，而非把月初状态重复计算三遍。

首版建议先支持具体行动列表。条件计划，例如“粮价超过某范围就开仓”，可在以后沿用计划接口扩展。

### 3.2 建议的旬内流程

1. **进入本旬**：建议根据旬初健康建立本旬行动力预算，不加入上一旬行动力余额；按诏书自己的规则更新本旬额度，扣除上一旬紧急透支的应还量，并根据游戏时钟检查 CD。具体数值公式与诏书常规补充方式待定。
2. **接收信息**：展示此时已经送达的奏报，将需要回应的紧急事件放入本旬待处理队列。
3. **确定活动安排**：接受玩家当旬安排，或读取月度计划；校验本旬行动力已全部分配，并记录是否安排处理朝政。
4. **执行与紧急中断**：普通政令逐项检查诏书、CD、劝谏及其他条件，不能透支诏书；在本旬安排全部结束前处理已送达的紧急事件。有朝政安排则不额外消耗行动力；没有则暂停，请玩家终止一个尚可中止的安排来处理。应急回应允许透支诏书并记录下一旬应扣量。劝谏等待玩家决定后再继续，实际执行与预估的差异保留记录。
5. **地方决策与世界结算**：官员根据本旬已知情况、职责、政策法律和收到的指派作出自主决策，与既有任务协调后提交行动；生产、收支、持续政策、地方处置、官员任务、人物变化及其他启用系统按明确依赖推进一次。
6. **生成结果与事件**：保存变化原因，形成官员报告与情报记录，结合情报机构、皇权及腐败规则更新皇帝可见事务和奏报；将符合条件的事件放入队列。建议完整旬末结算后才产生的急报归入下一旬，避免回头终止本旬已完成的安排。
7. **决定继续或暂停**：进入下一旬时，如有需要回应的紧急事件则暂停月度推进，并按新一旬的安排判断朝政覆盖；否则继续读取计划。

生产、财政、人物等系统内部的具体先后依赖尚待机制细化。框架须显式声明顺序，避免依赖文件加载或界面操作顺序。

### 3.3 紧急事件采用可恢复的暂停

本节将已确认的急报处理方式，与尚可调整的执行时点建议分开。

**已确认规则：**

- 只检查急报归属的当旬是否安排“处理朝政”；其他旬的朝政安排不能覆盖本旬急报。
- 当旬已安排朝政，则处理急报不额外消耗行动力。
- 当旬未安排朝政，则必须终止当旬某一个已安排的行动来处理。

- 紧急事件处理允许透支诏书，减少下一旬可用量；普通朝政命令不得透支。急报具有透支资格，不代表其回应不消耗诏书，也不改变以上行动力规则。

**执行建议：**在本旬尚有可中止安排时设置事件停靠点，例如一项活动执行之前或活动的可中断阶段结束后。每个实际状态更新步骤完整结束后，再等待玩家回应，不引入半次状态更新的恢复逻辑。

- 已执行行动和已完成结算保留，暂停不回退时间。
- 由玩家选择被终止的安排；已完成的活动不能被追溯终止。被终止的是本旬活动，不自动取消以后各旬的同类安排，也不自动撤销官员已经接到的长期任务。
- 尚未执行的计划保留，并允许玩家查看、修改或取消。终止活动后的进度、收益和资源损失规则待定，必须避免原活动获得完整收益后又免费执行替代活动。
- 恢复推进后从保存的位置继续，避免重复扣费、重复结算或遗漏行动。
- 紧急程度和是否必须打断由事件定义；没有必要打断的事件进入普通奏报。
- 需要玩家回应的紧急事件不能被月度自动推进跳过。
- 世界在完整旬末结算中产生的新事件，建议于下一旬送达并介入该旬安排；发生时间与送达时间分开记录。这样不会出现本旬活动已经全部完成，却仍要求终止其中一项的矛盾。

### 3.4 计划失效时的建议规则

若进入新旬时健康变化导致行动力与月初估计不符，或负责人离任、紧急透支导致诏书减少、CD 变化、资源不足、目标发生变化，则暂停受影响的安排并告知玩家，重新校验活动与指令的各项限制。普通政令不能借用未来诏书来维持月度计划；首版不默认替换目标或扩大支出。触发改税劝谏时，暂停月度推进并让玩家决定是否听取，不自动选择坚持。

计划中的长期事务指令只在安排的时点下达一次；后续进度由任务系统推进，不能因每旬读取计划而重复创建。

| 官员信息记录 | 官员已掌握的地方情况、报告、政策与指派及其更新时间，用于自主决策。 |
| 皇帝信息记录 | 对应对象、观察时间、来源、估计值或范围、信息可信程度、已暴露的事务及任务汇报渠道。 |
| 本旬活动安排 | 本旬行动力预算、各项活动的分配量、是否安排朝政、待执行／执行中／完成／终止状态及中止原因。 |
| 诏书额度与记录 | 本旬上限、已用量、可用量、应急透支量、下一旬应扣量及对应事件与命令；常规补充与结转规则独立配置。 |
| 行动定义 | 类型、可指定与可委托参数、前置条件、行动力或诏书等成本规则、频率限制及执行入口。 |
| 行动指令 | 发令人、执行者、目标、明确参数、委托参数、所属活动或急报、执行时点及执行状态。 |
| 政务频率状态 | 操作类型、限制对象、成功颁布时间、政策变更历史、CD 响应及惩罚所需记录。 |
| 劝谏与待提交命令 | 原命令、劝谏者、触发原因、玩家回应与提交状态；用于暂停、取消或坚持后继续。 |
| 政策与持续任务 | 生效条件、负责人、投入、进度、持续效果、结束与中止条件。 |
| 月度计划 | 三旬独立的活动安排与行动力预算、预拟指令、预计诏书使用量与 CD、当前执行位置、预估成本与暂停原因。 |
| 事件与回应 | 发生与获知时间、处理归属旬、紧急程度、适用停靠点、选项、被终止的活动及回应效果。 |
| 结算记录 | 状态变化、来源、参与人物和随机结果；玩家能看到的记录经过信息过滤。 |
| 存档 | 世界、政策法律、时钟与执行位置、各角色信息、地方事务与自主决策、活动与计划、诏书和透支记录、政务频率历史、待回应劝谏与事件、持续任务、随机状态及数据版本。 |

## 5. 扩展约定

- 新朝代主要通过新的开局内容接入；不同制度所需规则可以明确挂接，不将朝代名称写死在通用结算流程中。
- 新政务、私生活活动与事件，通过已有行动、人物、任务和事件接口接入。
- 新政策与法律通过适用条件、决策影响和行为规则接入；不为每个朝代另写一套相互隔离的地方官决策流程。
- 新系统声明它读取什么状态、负责更新什么状态，以及在何时结算；避免多个模块无顺序地修改同一指标。
- 所有正式状态变更通过受控执行和结算入口提交。界面、奏报和月度计划预估不直接修改世界。
- 保存随机状态与执行位置，使存档恢复后能够继续同一过程。诊断日志保存真实原因，玩家反馈遵守其已知信息边界。
- 首版选择少量系统跑通完整闭环，再补充历史内容与复杂机制。技术选型、完整官制和完整指标表尚未确定。

## 6. 首个可玩闭环建议

采用少量省／州、皇帝和几名官员，以“歉收—奏报—调粮或赈灾—执行—结果”为主线，辅以一个“休息”行动验证私生活入口与共享行动力。

月初分别安排三旬的全部行动力；地方官自行处理职责范围内的事务，上旬结算产生或加重灾情；依据情报、皇权、腐败等规则，建议中旬让皇帝获得相应奏报或急报。中旬有朝政安排时直接处理，没有时由玩家终止一项中旬活动；官员将赈灾指派与已有地方处置协调、补全委托参数；继续逐旬结算后收到带有信息误差的反馈。

该闭环可以检查：

- 逐旬操作与整月计划在相同行动、决策时点和随机初始状态下，产生一致结果。
- 中途暂停后可以准确继续，已完成行动与结算不重复执行。
- 健康变化后，未来行动按实际行动力重新检查。
- 明确参数与委托参数能在同一指令中共存。
- 玩家界面与计划预估不会绕过奏报直接泄露未知真值。
- 政务与个人活动使用同一套行动力记录。
- 每旬预算独立，推进前行动力全部分配，不跨旬结转。
- 本旬有朝政安排时，急报处理不额外扣除行动力；本旬没有时，必须实际终止一项本旬安排，不能用别旬朝政代替。
- 终止活动不会同时发放该活动的完整收益，不会撤销已完成活动，也不会连带取消下一旬安排。
- 一次朝政内可以下达多项命令，逐项消耗诏书，不重复扣除安排朝政的行动力；再次打开朝政不会恢复已用诏书。
- 仅预排命令不消耗诏书或启动 CD；成功下达后记录一次，恢复存档或暂停后继续不会重复提交。
- 各操作按配置的对象跟踪 CD 与历史；频繁修改税率适用对应惩罚，维持税率不计为修改。
- 听取改税劝谏后保持原税率，不扣诏书、不刷新 CD、不触发坚持惩罚；坚持则提交一次税率变化、忠心及声誉损失和适用效果。
- 频繁降税的民心收益与惩罚分开记录，结果保留被削弱的正向贡献；声誉惩罚不反向缩减不应获益的成本或负面后果。
- 普通政令在诏书不足时不能透支；紧急回应可以透支，并在下一旬仅扣一次对应额度，重新检查预排普通政令。
- 紧急事件透支资格不能扩展到同旬无关普通政令；劝谏和透支状态可随存档准确恢复。
- 皇帝没有具体指派或看不到地方事务时，地方官仍自主决策并推进世界；相同情况可因官员、政策或法律不同产生不同处置。
- 官员按自己掌握的信息决定方案，不无条件读取全国真值；皇帝可见性与信息误差分别经对应规则处理。
- 皇帝指派与地方自主处置重合时，同一事务与资源不被重复结算；官员自主行动不悄悄扣除皇帝的活动行动力或诏书。
- 相同真实状态下，改变情报机构或皇权可以改变皇帝看到的事务；观察规则本身不直接改变该状态的实际钱粮，也不自动赋予所有干预权限。

以上覆盖现有流程框架及未来完整模拟的验证目标；不能据此认为全部目标已经通过。当前实现范围见文首说明，皇帝属性技能页面已实现，世界数值、人物成长及财政机制尚未启用。
