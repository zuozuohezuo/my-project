## 直接体验

双击项目根目录的 `体验M03.cmd`，打开一局独立的 30 AP 示例。不会读取或覆盖玩家存档。普通“开始游戏”也已采用新规则；进入“02 起居与朝政”，点击“载入示范日程”即可。

1. 在“旬初 · 规划”调整工作与私生活分配。早朝固定 5 AP、日讲 1 AP；批阅章奏、召见臣工、宫廷事务先指定每段投入，再添加到日程；普通私人活动每项 1 AP。
2. 选择日程条目，用上下移动调整顺序。工作和私生活分别排满预算后，点击“开始依次执行”。示范为工作 20／私生活 10，共 15 项活动，早朝后穿插宫苑游赏。
3. 在“日程 · 执行”完成当前活动。早朝可逐项听取多个待办，也可进入“朝政 · 急报”下达诏令。散朝后，普通发令入口关闭。
4. 宫苑游赏可选择两处不同去处，花径见闻可生成后续宫务待办；读书可选择主题；习武有三轮手动节奏选择及按角色能力自动处理。场景选择不另扣 AP。
5. 在场景途中点击“插入演示急报”。有早朝安排则保留当前活动；没有早朝时，明确终止一项尚未完成的活动。处理急报后可回到原来的场景阶段。可在这里保存、关闭、读取以检查恢复位置。
6. 每项结束后查看小结，再开始下一项。全部日程结束后点击“完成本旬”，进入下一旬。人物目标与短期修正在这里结算一次。

## 办公与待办

本轮包含四项初始演示待办，分别属于章奏、召见和宫务。三类办公每投入 1 AP 推进一次工作量，支持复杂事项分段处理，未办完的进度随存档保留到后续时段或下一旬。没有工作时可在原分配时段整理案卷，不会挪用私生活预算。

早朝可以处理全部现有待办，没有按事项数追加的 AP 或隐藏容量。已在早朝办结的事项不会在后续批阅中再完成。处理待办与正式下令分开，只有正式政令使用诏书、检查冷却。

本轮演示效率为 `max(0.1, (1 + 相关技能 / 50) × 技能效果比例)`，显示值保留两位小数。召见采用识人，批阅与宫务采用政务处理。基础属性不另加常规办公效率。效率及复杂度都是便于试玩的参数，未作为正式平衡结论。

## 未来预约与三旬日程

“未来预约…”允许添加由时令、事件、准备条件产生的演示预约，期限可远于三旬。显示原定日期、当前日期、准备状态、所需 AP、冲突与变更记录。

到期要选择执行、改期或不去。执行把预约放入本旬对应预算，预算不足时提示玩家腾出位置，不覆盖已有活动。删除预约卡片会恢复待决定状态，不能绕过承诺。未决定的到期预约会阻止开始本旬。

改期保留同一个预约 ID 与原始日期，每次选择保存一条变更和对应后果；反复刷新、重复点击或读档不重复处罚。不去留下缺席记录。时令失期、来访信任损失、筹备损耗分别登记为待模拟效果；关系、礼制、财政等国家数值尚未实现，当前不虚构数值扣减。

三旬编辑器逐旬设置独立的预算与有序活动，可复制本旬到后两旬。预约不随普通活动复制到另一旬。预拟政令到实际早朝时才检查并提交；遇到事件选择、急报、劝谏或额度不足就暂停。未能下达的预拟政令必须继续处理或明确取消。

## 本轮暂定边界

- 新局健康档位暂为：80–100 提供 30 AP，40–79 提供 20 AP，其余 10 AP。只使用整旬整数 AP，没有每日额度、每日排程或现实时间计时。
- 固定活动在开始时计入全部成本；办公按实际完成的 1 AP 时段计账。预排阶段只预留。中止活动已用时间不返还，其余预算由急报占用并记录，不透支 AP。
- 只有早朝提供普通政令权限和急报朝政覆盖。其他工作的发令范围仍待设计。重复早朝不会补充诏书。
- 执行开始后锁定普通日程，比例与顺序可在旬初修改。提前结束办公、执行中任意重排、长期出游和更丰富小游戏留待后续。
- 私人活动留下过程、见闻、小结和完整完成记录；尚未自动增加技能、恢复健康、减少压力或发放目标奖励。
- 皇帝目标只累计创建之后实际完成的相应活动，每项完成记一次，办公多点 AP 不当成多次完成；中止和暂停不计完整完成。
- 国家钱粮、人口、官员实际任职与关系、自然事件、地方 AI 均未模拟。急报和预约来源目前由试玩入口手动添加，相关接口可供后续模块调用。

## 存档与验证

新规则存档版本为 2，包含日程、实际 AP、执行游标、场景阶段、待办、完成记录、目标计入边界、预约及后果记录。v1 旧档保留原来的 1／2／3 AP 配置与旧版页面，不擅自换算进行中的旧日程；旧局保存仍为版本 1。

`uv run python tools/capture_m03.py` 会创建九幅实际 Qt 界面预览及四份独立演示存档，保存到 `artifacts/`。示例只写项目内演示文件，不改玩家保存目录。

执行 `uv run pytest`、`uv run ruff check src tests tools` 和 `uv run dynasty --m03-demo --smoke` 检查代码。旧模块测试显式使用 v1 fixture；`test_m03_*` 使用实际 v2 新局，覆盖本轮新流程。
