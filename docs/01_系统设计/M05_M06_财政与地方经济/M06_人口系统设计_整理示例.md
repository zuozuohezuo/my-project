## 1. 概述

县级人口按职业、财富及居住身份汇总，为生产提供劳力，为消费提供人数与需求；每旬反映自然增减和资源短缺后果。玩家当前可在独立县试玩里查看真值并试调参数，正式皇帝治理及奏报入口未接通。

本系统负责人口底账、收入财富分档、劳力及短缺人口后果。真实工资支付、岗位匹配、迁移、年龄成长和正式财政属于后续工作。

## 2. 玩家体验与目的

设计目的：让生产条件与居民生活状态产生可观察的持续联系。当前可做的是改变演示供给／参数、推进整旬、比较报告；这属于原型验证操作，不是皇帝已经具备的赈济或直接编辑人口能力。

待验证的体验问题：玩家能否分清“钱池余额”“收入水平”“财富档”和“粮食供给”，并理解当旬短缺为何影响后续生产。这一体验判断尚未通过本次自动测试证明。

## 3. 现行规则与结算顺序

| ID | 规则 | 状态 |
| --- | --- | --- |
| M06-P01 | 七类职业：农民、劳工、手工业者、商人、地主、贵族、官员；每人属于一个主要职业组 | 已确认并实现 |
| M06-P02 | 财富按人均每旬收入相对基本生活成本分贫困、普通、富裕；与职业是同一人口的不同统计维度 | 已确认并实现 |
| M06-P03 | 取消年龄组，按全县劳动力比例、健康和劳动状态计算可用劳力 | 已确认的演示简化并实现 |
| M06-P04 | 所有群体共用县民间资源池消费；短缺按财富层脆弱系数产生不同后果 | 已确认并实现，系数为演示默认 |
| M06-P05 | 自然死亡先从期初存量扣除，再计算缺粮额外死亡；出生在旬末加入 | 现行演示规则并实现 |
| M06-P06 | 财富下降保持职业，同步调整收入；同一旬转层人口不按新档再受罚 | 已确认并实现 |
| M06-P07 | 收入参数不生成钱池收入，不另扣一遍生活成本 | 现行演示边界并实现 |

没有独立的人口行动状态机；财富是由收入派生的分类，健康、劳动状态和连续缺粮旬数是持久状态。当前结算连接为：

1. M03 真正完成一旬后调用县经济结算，校验连续旬编号并复制候选状态。
2. 使用当旬人口和劳力完成生产，再按当旬群体需求完成消费。
3. 用期初群体快照计算自然出生和自然死亡总量，分摊到群体；计算消费满足率对应的后果。
4. 对各原群体扣自然死亡、缺粮死亡，改变健康／满意／劳动状态，计算存活人口的财富下降。
5. 统一合并转层人口，再加入新生人口；新生人口当旬不参加生产消费或死亡计算。
6. 保存小数余量、报告与最新结算旬，验证后返回候选结果。刷新、暂停和读档不增加结算次数。

出生下一旬直接纳入整体劳力比例，是本版取消年龄模拟后的简化，不代表婴幼儿真实劳动能力。

## 4. 数据、单位与归属

| 数据 | 归属及单位 | 使用边界 |
| --- | --- | --- |
| `cohorts[].count` | 县人口群体，非负整数人 | 职业和财富汇总不能相加成为另一份人口 |
| `occupation / wealth / resident_status` | 职业／财富档／本地或流民身份 | 有流民身份记录不表示迁移已经运行 |
| `income_per_capita` | 演示钱单位／人／旬 | 当前是分档依据，不是实际工资收付 |
| `health / satisfaction` | 0–100 状态值 | 县民健康独立于皇帝 `GameState.health` |
| `labor_factor` | 0–1 比例 | 与健康和全县劳动力比例相乘 |
| 出生／死亡／降层余量 | 全县或群体持久数据 | 小数保留到后续旬；随存档恢复 |
| 资源池余额 | `GameState.economy.pools` | 消费只扣民间池；官府和皇家池不自动补缺口 |

县页当前展示演示真值；正式情报权限由未来 M07 提供。

## 5. 公式与示例

### 人口与劳力

```text
P = Σ n_i
基础劳力 = P × r
可用劳力 L = Σ(n_i × r × h_i / 100 × f_i)
```

`n_i` 为群体人数，`r` 为全县劳动力比例 0–1，`h_i` 为健康 0–100，`f_i` 为劳动状态 0–1。输出满足 `0 ≤ L ≤ P×r`。正常初值 P=1,000、r=0.5、h=100、f=1，因此 L=500。此例来自演示配置。

### 收入分档

```text
贫困：0 ≤ I < C
普通：C ≤ I < C × m
富裕：I ≥ C × m
```

`I` 为人均每旬收入，`C>0` 为基本生活成本，`m>1` 为富裕收入倍率；当前 C=1、m=3。收入 0.6 为贫困，1 为普通，3 为富裕。跨档合并按人数加权状态，人数不变；钱池不随分档改变。

### 自然增减及人口守恒

```text
本旬期望出生 = P × 年出生率 / 36 + 上旬出生余量
本旬出生 = min(P, floor(本旬期望出生 + 1e-12))
新出生余量 = clamp(本旬期望出生 - 本旬出生, 0, 小于1的最大浮点数)
自然死亡使用同类累计方式，再按原群体人数分摊
期末人口 = 期初人口 + 出生 - 自然死亡 - 缺粮额外死亡
```

年率是按 36 旬折算的名义率；人口每旬改变，全年数量不保证等于开局人口乘年率。用 1,000 人、年出生率 0.03、初始余量 0 演示：首旬期望出生约 0.8333，整数出生 0，小数留存到后续旬。群体分摊使用确定性算法，代码见 `_fractional_events` 与 `_apportion`；不是各群体分别取整。

### 短缺死亡与恢复

```text
缺粮比例 g = 1 - 口粮满足率，0≤g≤1
连续缺粮放大 A = 1 + min(max(连续缺粮旬数-1, 0), 上限) × 增幅
财富档额外死亡率 q = min(1, g × 基础缺粮死亡率 × 财富脆弱系数 × A)
自然死亡后存量 N = 原群体人数 - 自然死亡
缺粮死亡 = min(N, floor(N × q + 该群体死亡余量 + 浮点容差))，q=0时为0
```

贫困、普通、富裕脆弱系数严格递减。健康和劳动状态按缺粮比例扣减，在口粮完全满足时按恢复参数回升并限制在合法区间。日用与享受品短缺影响满意度及降层，不直接进入上述缺粮死亡率；实际合并、降层和余量搬运顺序见[人口实现](../../../src/dynasty/core/regions/population.py)。本节列主要公式，完整细节以该函数和原专题为证据，不据此推断经济必然不可恢复。

## 6. 边界情况

| 情境 | 当前行为 |
| --- | --- |
| 零人口、零消费需求 | 不除零；零需求满足率为 1；无人口来源时不会凭空出生 |
| 小群体不足一人自然增减 | 全县累计整数后分摊，避免每群体取整造成永久停滞 |
| 极高死亡率 | 自然死亡先扣，缺粮死亡不超过剩余人口 |
| 同旬财富下降 | 按原群体受罚一次，再合并；保持职业和全县人数 |
| 全部供给恢复 | 按恢复参数回升，不保证全部状态瞬间满值；不会自动恢复原收入档 |
| 中途存读或更换群体顺序 | 保存余量与旬序，采用稳定分摊；不重新随机分配或重复结算 |
| 旧县经济 v1 | 使用冻结旧规则；不猜测职业和收入，不提供新版人口参数编辑 |
| 数据损坏或经济旬序不连续 | 拒绝读取／结算，不静默重建县，不提交部分后果 |

## 8. 可调整参数

参数来源：[county_demo.json](../../../data/config/county_demo.json) 的 `rules`。当前存档保存自己的副本。

| 参数 | 当前默认 | 程序范围 | 已验证平衡范围 | 增大后的直接作用 |
| --- | --- | --- | --- | --- |
| 劳动力比例 | 0.5 | 0–1 | 尚未建立正式范围 | 同状态下可用劳力增加 |
| 年出生率 | 0.03 | 0–1 | 尚未建立正式范围 | 期望出生增加，后续需求和劳力也改变 |
| 年自然死亡率 | 0.02 | 0–1 | 尚未建立正式范围 | 自然死亡期望增加 |
| 基本生活成本 | 1 | 大于 0 且相关运算有限 | 尚未建立正式范围 | 同收入更容易落入低财富档，不直接扣钱 |
| 富裕收入倍率 | 3 | 大于 1 且相关运算有限 | 尚未建立正式范围 | 富裕门槛提高；当前页面不提供该项编辑 |

前四项可在新版县演示旬初调整，收入也可按群体编辑。执行中拒绝修改。代码合法范围只是输入约束；测试几个情境不意味着整个范围都已平衡。

## 9. 界面与反馈

县档案“人口”页显示职业、财富、群体收入和参数；“民情与秩序”及历史旬报展示状态与后果。财富统计和职业统计均需读作同一批居民。坏输入提示原因并保留原值；旧县说明按旧规则运行。正式奏报、隐藏信息和治理选项仍待设计。
