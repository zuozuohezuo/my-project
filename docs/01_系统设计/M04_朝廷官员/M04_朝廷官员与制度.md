## 1. 本模块要解决的问题

M04 负责朝廷由谁任职、各职位能办理什么、官员怎样表达意见，以及政令交给官员后如何执行和接受监督。建议按以下六部分逐项讨论：

| 子方向 | 要设计的内容 | 主要玩家操作 | 脚本责任建议 |
| --- | --- | --- | --- |
| M04-01 官员档案 | 能力、性格、履历、操守、政治主张与个人追求 | 查看、了解、比较候选人 | 复用 M01/M02 的人物规则；任职与政治档案由 M04 维护 |
| M04-02 官制与职权 | 机构、职位、职责、辖区、兼任、制度与法令约束 | 查看职权、调整制度、确定办理责任 | 拟新增 `core/government/offices.py`、`policies.py` |
| M04-03 任免与仕途 | 举荐、任命、升降、调任、罢免、离任与到任 | 选人、用人、换人 | 拟新增 `core/government/appointments.py` |
| M04-04 朝议与劝谏 | 谁参加、谁提案、支持理由、反对理由、实际办理权 | 提案、听取意见、决定处置 | 拟新增 `core/government/council.py` |
| M04-05 执行与考核 | 自主办理、奉旨办理、进度、成果、偏差、问责 | 委派、追问、考核、奖惩 | 拟新增 `core/government/execution.py`；与 M06/M07 协作 |
| M04-06 关系与政治局势 | 君臣关系、官员之间的关系、利益群体、政府声誉与腐败 | 了解关系、处理冲突、调整人事与政策 | 具体数据结构和脚本拆分待讨论 |

表中 `core/` 指 `src/dynasty/core/`；拟新增脚本均尚不存在。按用户最新顺序，先核历史机构官职清单，再讨论游戏职权与作用，随后展开官员、任免、朝议与执行。政令的 AP、诏书成本及执行时机沿用 M03，不在此重新定价。

## 2. 延续的已确认规则

- 官员能力、性格及少量随机性影响执行；地方官在没有皇帝具体指派时，仍依据国家方针、法律与自身所知情况自主治理。
- 官员依据可掌握的信息行动。世界真实状态、官员所知和皇帝所知须保持区别；制度职权、信息可见性与实际执行结果分别处理。
- 改税 CD 内的劝谏可以听取取消，也可以坚持执行并承担既定政治后果。此机制不自动推广到所有反对情形。
- 特定宫廷享乐划拨须在朝堂提出。财政糟糕且大臣清廉、坚持道德原则时，会强烈反对；如其为财政主官，罢免前不能进行该笔操作。
- 继任财政主官重新处理同一个方案，其性格仍会影响态度，仍可能阻止。职位空缺的办理方式尚未确定，不能把空缺视为自动放行。
- 上述财政主官的实际阻止权不能由皇帝坚持、额外诏书或技能判定绕过，也不自动推广为所有支出的普遍否决权。

官员自身是否完整复用皇帝的 13 项基础属性、技能与九组性格，以及新增哪些专属字段，是本模块接下来要确认的设计；已有 M01/M02 的能力与学习原则保持不变。

## 3. 建议先分清人物、机构、职位与任职

| 对象 | 保存什么 | 换人或调任时怎样变化 |
| --- | --- | --- |
| 人物 | 身份、能力、健康、性格、经历及个人追求 | 随人物保留，不因离任清空 |
| 机构 | 负责的事务、人员编制、工作流程、待办及组织资源的引用 | 主官更换后仍保留；钱粮余额由 M05 管理，不成为主官私产 |
| 职位 | 名称、职责、可办理事项、辖区与制度限制 | 随剧本或制度改变，不附着于某个人 |
| 任职记录 | 谁在何时担任何职、是否实际到任、是否兼任或暂代 | 任免改变记录；具体生效时点待定 |
| 关系与政治记录 | 谁信任谁、何种关系、某人对某议题的立场 | 依关系对象与事件变化，不继承前任的私人关系 |

这是建议的数据分工，官员详情页可以同时呈现这些信息；办理权限从有效职务获得。跨朝代可使用不同官制资料，正式职位表与历史准确度在具体剧本中核查。

例如同一位官员从其他职位调任财政主官，其能力与性格沿用，职权随任职变化；前任对某方案的态度留作历史记录，继任须重新判断。不能直接复制前任的同意或反对结论。

## 4. 官员档案的候选维度

以下是供选择的内容，不立即增设新的数值量表：

| 内容 | 建议表现 | 与既有系统的关系 |
| --- | --- | --- |
| 身份与经历 | 年龄、出身、籍贯、仕途经历、实际经办记录 | 身份和历史资料可引用；出身不自动等于能力或道德评价 |
| 能力与健康 | 复用适用的基础属性、技能、健康、压力与修正 | 相同技能、修正及其他条件下常规表现一致；不把高基础属性变成普通效率额外加成 |
| 稳定性格 | 优先复用 M02 九组倾向 | 不仅因是官员就另建同义性格轴；具体官员效果逐项设计 |
| 操守与政治主张 | 清廉等特质、重视的公共目标、对具体政策的判断 | 与性格、私人利益及所知情况共同影响态度；量表、标签或经历推导方式待选 |
| 个人欲望与野心 | 对仕途、家庭、财富、名誉或政治目标的追求 | 可参考 M02 的追求结构；官员自主追求机制尚未确认或实现 |
| 关系与政治评价 | 对皇帝的关系、与其他官员的联系、公开声誉 | 忠心的对象和含义仍待定；关系和公开评价与实际能力、操守分别保存 |

不把“支持皇帝的某个方案”直接当作忠心或能力证明。对一项提案的态度可以随财政信息、利益影响或方案本身变化；稳定性格保持较慢变化。清廉、仁厚、守信等概念如何关联，需要逐项定义，不能互相直接替代。

人物真实字段不默认全部呈现给玩家。皇帝通过履历、奏报、召见、考察等了解官员的具体方式和可见精度留给 M07 共同设计。史料评价也不自动转换成精确人格分数。

## 5. 当前需要选择的模拟层级

此前曾向用户询问以下范围；用户现要求先核定机构和官职清单，模拟层级暂缓选择：

1. 中央核心官员与地方主官作为独立人物，其余属员先概括处理。
2. 各级官员均作为独立人物，可逐级查看和管理。
3. 先细化中央朝廷，地方官员以后展开。

建议第一种作为初步讨论范围，便于先把任免、劝谏和执行关系做完整；此建议不代替用户选择，也不提前确定人物数量、基层编制或模拟性能方案。若选择较细层级，仍可通过机构汇总界面降低玩家逐人管理负担，具体自动管理权限另议。

## 6. 后续讨论与模块边界

按用户最新指定顺序，先核历史机构官职，再讨论游戏作用；人物档案与模拟层级可随后展开，尚未决定任何正式数值：

1. 参考历史确定机构与官职目录，区分中央、内廷、地方、军政与差遣。
2. 为选定机构与职位讨论游戏作用，各类事务由谁提出、谁审议、谁具体办理；再确定人物模拟层级与官员专属内容。
3. 任免资格、兼任与实任、职位空缺、到任时点、调任与罢免后果。
4. 朝议参与、官员立场与理由、普通劝谏和实际阻止的适用范围。
5. 执行进度、失误与利益影响、汇报、考核和奖惩。
6. 人际联系与利益集团怎样形成、影响意见及执行，制度如何变更。

M04 提供任职、职权、对提案的判断和通用执行约束。M05 负责账户与资金移动，M06 负责地方生产和治理结果，M07 负责观察与奏报，M08 提供具体事件与持续任务，M03 负责活动执行时机、暂停和恢复。官员自主办理不默认逐件消耗皇帝 AP 或诏书，具体需要皇帝裁决的事项再进入相应活动。

当前代码仅有史料人物、官职与法令资料、任命意图及改税劝谏演示，尚无完整任职、官员人格运算、关系网络、财政主官阻止或政治数值结算。本稿不代表这些玩法已经实现。
