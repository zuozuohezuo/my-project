# 明中期史料起步包：人物、官制与法令

> 2026-09-10 分类说明｜历史研究资料：用于查证和设计参考，不表示已纳入运行模拟。 [当前实现核对](../00_项目总览/系统索引与实现状态.md) · [工作文件总入口](../README.md)

本包把 **弘治十三年（1500）农历正月** 作为临时工作快照。这是为搭建框架选定的基准，尚未代替用户决定最终开局。真实任职、后出的制度说明、人工归纳和游戏数值分别保存；史料不会自动驱动人口、粮食、财政或人物属性变化。

地图与行政区划由同目录其他资料包负责，本文不声明其边界或府县核对范围。

主要依据是[《明史·七卿年表》](https://zh.wikisource.org/wiki/明史/卷111)的弘治十二、十三年行与列标题、[《宰辅年表》](https://zh.wikisource.org/wiki/明史/卷109)的弘治十一至十三年记录，并对照[《孝宗本纪》](https://zh.wikisource.org/wiki/明史/卷15)、人物列传和[《明通鉴》卷43](https://zh.wikisource.org/wiki/明通鑑/卷043)。表中一些名字只写单名，不能把脱离列标题的“经、珪、贯”直接作为完整人名。

正月六部任职是由上一年连续任职、当年五月离任和《明通鉴》完整职名记载归纳的。JSON明确写有“开局时间归纳”，不冒称取得了每位官员正月初一的直接点名名册。《明通鉴》本身使用《明史》等材料，并不是对每个事实完全独立的第二位同时代见证。这里所说“互核”指纪年、年表、列传和另一部编年史之间的相容核对，尚非原始档案的多底本校勘。

阁臣的尚书兼衔与实际掌部岗位分别存储。例如刘健有户部尚书兼衔，但开局实际户部尚书是周经。后续史实变动放在 `time_applicability.later_changes`，并标识仅供参考；玩家改变历史后，游戏不应无条件重演这些调任或退休。

佀钟在网页篇目、正文中出现“佀鍾、似鐘、侶鐘”等录文差异，原文保留，不静默覆盖。游戏显示名采用“佀钟”，别名及待影印本复校状态同时保存。

## 官制怎样用于框架

职官目录能够支持查阅、人物任职引用和未来的权限配置，暂不作为全国实有编制表。明代“省”是开发中对布政司等大区的方便称呼；布政使司、按察使司、都指挥使司分管不同事务，其辖境和隶属关系不应被压成一条单一行政树。两京直隶也不能自动添加与其他省相同的三司。

巡抚、总兵等差遣与本官衔分开看待，不能直接套用清代的统一督抚编制。州也分直隶州与属州，“州”不自动等同省级地区。职官来源主要为[《明史》卷72](https://zh.wikisource.org/wiki/明史/卷72)、[卷73](https://zh.wikisource.org/wiki/明史/卷73)、[卷74](https://zh.wikisource.org/wiki/明史/卷74)、[卷75](https://zh.wikisource.org/wiki/明史/卷75)、[卷76](https://zh.wikisource.org/wiki/明史/卷76)。这些篇章包含全明沿革，已避免把书中嘉靖、隆庆、万历新增的编额直接写成1500的数量。

朝政劝谏可以引用六科、御史与阁臣的制度背景；私生活可以以后接太医院、司礼监和宗人府资料。健康、行动力、忠心、人格、机构强度等游戏值仍应来自单独的设计配置，不以史书褒贬直接生成分数。

## 法令版本边界

已下载的《大明律》网页实际题名为**《大明律集解附例》**，内含律文、集解、纂注、会典和后附条例。十项结构化内容只概括律文主题：选官权限、奉制执行、应奏事项、文书稽程、户籍、灾伤田粮勘验、收粮量器、官吏受财、堤防和桥路维护。处罚数额、刑罚算法及后附条例均未启用。原文中的字形和疑似讹字仍以存本为准。

1500年二月重定问刑条例的时间，可由[《孝宗本纪》](https://zh.wikisource.org/wiki/明史/卷15)与《明通鉴》核对；[《明史·刑法一》](https://zh.wikisource.org/wiki/明史/卷93)记可行条目297条。JSON将该记录明确标为**晚于正月开局、未生效的参考事件**。尚未取得并逐条校录这297条的独立原刊，不能将网上带万历后附例的整本替代它。

[《大明会典》御序](https://zh.wikisource.org/wiki/大明會典/御製大明會典序)分别署弘治十五年、正德四年、万历十五年。已保留这份原典作为版本年代证据，说明为何不能把后出的会典整体视为1500年已经颁行的制度。后世会典仍可提供早期制度线索，但必须继续按每条所标年代筛选。

用户约定的诏书上限、紧急透支、政务CD、忠心与政府声誉惩罚属于**游戏规则**。现有史料不证明明朝皇帝每旬有固定诏书张数，也不证明改税有某一固定冷却时间。两类资料应持续分离。

## 复现与核验

在项目根目录运行：

```powershell
uv run --group research python tools/download_people_laws.py
uv run --group research python tools/build_people_laws.py
uv run python tools/verify_history_people_laws.py
```

下载器默认保留已有存本；明确需要重新获取时加 `--refresh`。网络异常会记作失败并返回非零状态，不能静默变为成功。构建器检查每项人工证据锚点确实出现在已保存的正文中，缺失便中止。核验器检查HTML与TXT校验和、稳定ID、人物官职引用、来源引用、全部证据摘录、若干重要时间边界及无伪造人格分数。

核验通过只能证明文件和引文一致，不能证明史书本身无误。资料包保留的是公开录文，不是逐页校勘后的影印底本。

## 来源与复用

古代原典作者已逝世逾百年，作品本身属公有领域；维基文库页面另包含现代校录、标点、界面和贡献内容，应保留来源与适用署名。每份下载的原始URL、修订链接、时间和许可备注保存在来源清单。无需游戏运行时联网。

已查[哈佛CBDB官方下载说明](https://cbdb.hsites.harvard.edu/download-cbdb-standalone-database)及[商业授权说明](https://cbdb.hsites.harvard.edu/exclusive-commercial-license)，其数据含非商业性许可条件及独占商业授权说明。本次没有把CBDB数据并入游戏包，使用已公开原典人工整理人物，以保留后续发行选项。官网只是被核对的候选来源，不能写成“CBDB数据库已下载”。

初次遇到的空正文选择器、一次诊断请求403及解决情况都记录在 `sources_people_laws.json` 的 `discovery_notes`。现有23份原典下载和正文检查均已成功。

## 留给用户及后续研究的确认项

1. 最终开局年份与具体月份。暂用1500农历正月，年份改变后必须重筛任职与制度。
2. 是否采用更细的朝廷完整名册，是否给地方官全部使用真实人物。当前省府州县岗位资料齐备，但全国地方官任职名册尚未整理。
3. 人物能力、性格与关系的生成方法。当前一概不设历史性格分数。
4. 官职、兼衔与实际差遣对玩家权限的具体约束；官员自主开仓、减税等行为仍保留待设计。
5. 农历闰月、历法换算和年龄算法；月份仅为游戏旬历框架，尚非历日复原。
6. 史料叙述中的褒贬、疑案、姓名异体和日期分歧采用何种展示方式。
7. 《大明律》洪武定本、弘治问刑条例原刊及相关会典条目的逐条版本校勘。
8. 所有史料引用在公开发行时的署名、现代校录复用和资源打包范围。

这些待确认项均不阻止行动力、地图、朝政指令和仅推进时间的框架运行。
